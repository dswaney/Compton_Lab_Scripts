       $files = @('00_Update-Scripts-FromShare.ps1','Update-DeploymentManifest.ps1',
           'Watch-RebootRecovery.ps1','RepairScreen.psm1','Show-RecoveryNotice.ps1')
       foreach ($name in $files) {
           $tokens=$null; $parseErrors=$null
           [void][System.Management.Automation.Language.Parser]::ParseFile(
               (Join-Path $PWD $name),[ref]$tokens,[ref]$parseErrors)
           if ($parseErrors.Count) {throw ($name+': '+($parseErrors.Message -join '; '))}
           Write-Host ('PASS: '+$name)
       }
   }

   and invoke watchdog -Deploy to install into protected ProgramData and
   register the one-minute watchdog plus startup notice task.
   Installation does NOT call -Force, thaw, freeze or reboot. The installed

   -Deploy defers for a running watchdog, missing configuration, unavailable
   DFC state, frozen computer, inaccessible receipt storage, or an active/

   A deferred installation is a warning in the 00 updater log, not a fatal
   updater failure that would stop Script 01. Retry on a later thawed 00 run.
   Completed receipts and cooldown are preserved; deployment does not archive
   incidents or reset attempt budgets. Deployment during recovery is deferred.

SERVER SETUP (Linux server only; no Python required on endpoints)
Copy Configure-RecoveryShare.py to /home/dswaney on 10.2.12.4, then:
  sudo python3 /home/dswaney/Configure-RecoveryShare.py
The script finds exactly one existing share section under /etc/samba/*.conf,
backs it up plus root/pilot ACLs under /root/recovery-share-backup-*, changes
only that share, validates testparm and reloads Samba without a service restart.

Root Domain Computers permission is write/traverse without listing. Sticky bit
blocks deleting/renaming folders owned by other accounts. Default child ACLs
allow creator owner plus dswaney and Domain Admins, with no broad computer
group grant. Administrators can use sudo on Linux for root-level cleanup.
Existing child contents and permissions are not recursively rewritten.
A name squatter can deny service by reserving another computer's folder name,
but the ownership checks refuse to trust that folder. Investigate owner mismatch.

For a NEW pilot, copy the runtime files and run 00 through Action1 as SYSTEM
while thawed. Check the Installed watchdog event and verify the new folder's
owner on Elastic with: sudo getfacl -p /srv/compton-reboot-recovery/COMPUTERNAME
Then test that another computer account cannot read that folder.
